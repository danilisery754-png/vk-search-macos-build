## Исправлено в v0.3.3

1. HTTP 500 при старте браузерной авторизации и окна сообщений устранён переводом FastAPI routes в активный asyncio loop.
2. Запуск авторизации имеет Edge-first и bundled Chromium fallback; текст сбоя не содержит токен или OAuth URL.
3. Старые раздельные тексты объединяются в один список. Для группы выбирается один стабильный вариант и используется для обоих способов отправки.
4. ЛС и предложенная запись выполняются независимо и последовательно, поэтому закрытый первый способ не блокирует второй.
5. Вкладки настроек больше не используют якоря и не прокручивают интерфейс вниз; карточки главной страницы адаптируются к узкому окну.
6. Inno Setup больше не ждёт WebView2 bootstrapper без собственного таймаута, поэтому мастер установки не может остаться навсегда на полной зелёной полосе.

## Обязательная проверка Windows-артефакта

Сценарий `build/BUILD_WINDOWS.ps1` создаёт установщик только после четырёх успешных запусков уже собранного EXE:

1. `--self-test`, запуск 1;
2. `--self-test`, запуск 2;
3. `--browser-self-test`, запуск 1;
4. `--browser-self-test`, запуск 2.

Любой ненулевой exit code прерывает сборку и сохраняет traceback. Это проверяет локальный сервер, интерфейс и фактический запуск упакованного Chromium без зависимости от Python/PyCharm пользователя.

## Честная граница проверки

Самотест браузера не вводит логин, пароль или 2FA пользователя и не отправляет реальные обращения. Живой VK-вход, права выданного токена, ЛС, предложка и inbox принимаются пользователем по `docs/VK_LIVE_REGISTRY.md`. Перезагрузка компьютера для исправления HTTP 500 не требуется.
